# Swagger Petstore API Testing

## Project Status

**Completed – API test design, Postman implementation, manual execution, Collection Runner execution, and test reporting completed.**

## Project Overview

This project covers functional API testing of the Swagger Petstore API using Postman.

The collection includes all 19 documented operations for Pet, Store, and User resources, as well as selected negative tests and end-to-end workflows.

## End-to-End Workflows

### Pet

Create → Retrieve → Update → Update with query parameters → Upload image → Delete → Verify deletion

### Store

Create order → Retrieve order → Delete order

### User

Create → Login → Retrieve → Update → Logout → Delete

Some Store and User workflow steps were blocked by HTTP 500 responses from the public API.

## Observed API Issues

* Image upload returns a Pet object instead of the documented ApiResponse schema
* Valid Store requests return HTTP 500
* Multiple valid User requests return HTTP 500
* Login accepts invalid credentials and returns a session
* Missing required Pet fields result in HTTP 500 instead of a client validation error

## How to Run

1. Import the Postman collection and environment from the `postman` folder.
2. Select `Swagger Petstore - Local` as the active environment.
3. Set the following environment values:

```text
baseUrl = https://petstore3.swagger.io/api/v3
apiKey = special-key
```

4. Set a test value for the collection variable:

```text
userPassword = any test password
```

5. Open Collection Runner and run one iteration.

Dynamic IDs, pet names, usernames, and email addresses are generated by the Setup request.

The following requests should only be executed when their test resources are successfully created:

* DELETE Order
* DELETE Pet without Authorization

The image upload request requires selecting a local binary file and can be executed manually.
